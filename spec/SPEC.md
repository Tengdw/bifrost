# Bifrost 首版系统规格

状态：首版开发基线。第 01–09 票实施了当前持仓里程碑，验收使用合成数据；定时、日终与收益尚未实施。本文定义首版必须交付的行为和验收条件。字段、计算公式与运维步骤分别维护在对应专项文档中。

## 1. 用户与交付边界

面向管理多个币安账号的同一位用户。用户应能回答：选中的账号在某一时点持有什么、值多少美元；一天的资产变化里，多少来自外部资金进出，多少是盈亏；数据不全时，哪部分不能下结论。

| 纳入首版 | 范围之外或待验证 |
|---|---|
| 独立币安账号及持有独立密钥的子账号；现货、资金、Simple Earn 活期与定期、普通 U 本位合约；币安直接持有的美股 | 不接外部券商、统一账户或其他理财产品；不自动发现子账号，不下单、不提币 |
| 已核验的资金钱包美股按原始代码保留股数，按资产类别单列美股 | bStocks 暂无非零实测样本，保留原钱包余额口径，标待验证；不推算成直接持股 |

## 2. 从接入到查看历史

| 步骤 | 系统必须做到 | 实现依据 |
|---|---|---|
| 接入账号 | 在受保护的页面绑定只读凭据，以稳定的交易所身份识别账号；换密钥沿用历史，停用后停止同步但历史可查 | [蓝图](../Docs/资产记录系统首版蓝图.md)、[数据模型](../Docs/数据模型与约束.md) |
| 采集 | 单个 Go 服务启动时同步，其后每 15 分钟同步。手动刷新复用同一采集流程，同账号同钱包的在途请求合并；一个钱包失败不阻断其他钱包 | [同步规则](../Docs/同步流程与异常处理.md)、[技术栈](../Docs/首版技术栈.md) |
| 记账与估值 | 保存原币数量、观察时间、当时的价格与来源；Go 计算 USD 权益。流水用于解释变化，不叠加到余额。PostgreSQL 只存数据，无物理外键，不调度任务 | [资产口径](../Docs/资产口径与币安接口映射.md)、[数据模型](../Docs/数据模型与约束.md) |
| 展示与核对 | 支持按账号筛选；主卡和环图共用最近已结束日的同一边界。按钱包和按资产类别分别分组；7/30/90 天走势与月历读取同一天的同一套指标，点击日期能核对期初、期末和净流入 | [UI 设计](../Docs/资产统计看板UI设计.md)、[OpenAPI 契约](../Docs/API契约.yaml) |

**完整性按指标判断。** 只要缺一个应纳入的钱包或持仓价格，完整总额就返回 `null`；可另列已估值小计、旧值的观察时间和缺失原因。反过来，持仓和价格齐全但充提流水缺失时，仍可显示权益和资产变化，盈亏及收益率留空。以北京时间划分自然日，新接入账号、资金划转和同步失败都不得制造虚假涨跌。

## 3. 跨模块验收

下列场景贯穿采集、存储、API 和 UI。开发时用合成数据复现，实盘联调另用只读账号核对；示例不包含个人余额。

| 场景 | 应看到的结果 |
|---|---|
| 资金钱包有价值 800 USD 的现金和价值 200 USD 的直接美股，其他钱包为零；另一接口也返回同笔股票 | 钱包视图资金为 1,000；类别视图美股为 200、其他为 800。股票缺价时保留股数；资金钱包和组合的完整总额均为空，已估值小计均为 800。其他空仓钱包仍为零；按类别看，美股金额为空，其他资产仍为 800。所有占比为空 |
| 期初 10,000 USD，中午入金 2,000，期末 11,900 | 当天资产变化 +1,900，盈亏 −100，时间加权现金流口径下的日收益率约 −0.91%；折线和日历明细一致 |
| A 向 B 转 500 USD，无费用、无价格变化；重跑一次流水同步 | 仅选 A：变化 −500，净流入 −500，盈亏 0。选 A+B：外部净流入和盈亏均为 0。重跑不增加流水 |
| 00:00 的边界批次只有三个钱包成功，第四个到 00:08 才恢复 | 恢复的观察可更新当前明细，但不能补成 00:00 完整快照。受影响日历显示缺失和原因，曲线不画成归零 |
| 备份恢复到隔离库并关闭调度 | 用匹配版本的密钥读取数据但不打印凭据；历史日权益、流水和最近完整批次与基线一致，演练期间不发起真实账户同步。详见[部署与恢复](../Docs/部署与恢复.md) |

## 4. 开工顺序与上线条件

1. **先交付可对账的当前持仓。** 从“一个只读账号 → 四钱包原始持仓 → 一批 USD 快照 → 总览与明细”打通，再用第二个账号检验隔离和汇总。价格源未接通时先验数量和缺价行为。进入实盘估值前，须验证 USDT/USD 价源及时间戳、资金冻结或在途字段的计入规则、合约账户模式；美股休市没有核验过的收盘价就不出估值。
2. **再交付可回看的历史。** 接入定时采集、观察窗口与日终边界，验证重复刷新、重启、数据迟到和权限失败。未采到的历史余额不补造。
3. **最后交付能解释的收益。** 对齐流水覆盖、转账配对与日内现金流，再启用可靠的收益指标。真实上线前验证受保护入口、凭据轮换、唯一调度实例和隔离恢复。bStocks 验证不阻塞已确认的直接美股接入。

变更范围、估值口径或缺失数据行为时，先更新对应专项文档，再同步受影响的 API 字段、本规格验收场景及 UI 说明。
