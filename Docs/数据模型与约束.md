# 数据模型与约束
首版逻辑表设计，供编写迁移和 sqlc 查询时使用。本文件不是已执行的 DDL。PostgreSQL 只存记录；**所有关联均为普通字段，无物理外键，无业务触发器、存储过程或数据库任务队列**。估值、配对、收益计算与校验在 Go 完成。

## 约定
内部 ID 使用 UUID；交易所 ID 作为 TEXT，保留原文。数量、价格、汇率和金额用 NUMERIC，不使用浮点；Go 用十进制计算，不在入库时统一截成两位。时间用 TIMESTAMPTZ（UTC），展示日为 Asia/Shanghai 的 DATE。缺值存 NULL，真实零为 0。币种包含命名空间，不能只按同名 ticker 合并不同资产。

## 表与粒度
下表除特别列出的复合键外，各表有独立主键 id。U 表示唯一索引，不是跨表约束。

| 表 / 一行代表 | 关键列 | 唯一性与用途 |
|---|---|---|
| accounts / 一个交易所身份 | exchange, exchange_uid, alias, enabled_from, disabled_at, last_verified_at | U(exchange,exchange_uid)；通过只读接口核实稳定身份后激活；未知 UID 不以别名或密钥哈希代替入账 |
| account_credentials / 一版凭据 | account_id, version, ciphertext, nonce, master_key_version, active | U(account_id,version)，每账号至多一个 active 的部分唯一索引；密钥轮换不换 account_id |
| wallet_scopes / 一段覆盖期 | account_id, wallet, valid_from, valid_to, support_state, reason | U(account_id,wallet,valid_from)；Go 防止覆盖期重叠，区分确认未开通与权限未知 |
| batches / 一次组合采集 | scheduled_for, trigger, started_at, closed_at, requested_scope, state | 定时批次按 scheduled_for 部分唯一，手动批次另建；冻结本次目标账号及钱包 |
| wallet_runs / 一批内一个账号的钱包 | batch_id, account_id, wallet, observed_from, observed_to, last_success_at, state, reason, attempt_count, mode | U(batch_id,account_id,wallet)；已观测但缺价可保留原始数量 |
| holdings / 一次观察中的一个资产项 | run_id, item_key, asset, asset_class, underlying_symbol, quantity, components, raw_unit, usd_value, price_id | U(run_id,item_key)；现货/资金按币，活期按产品，定期按 positionId，合约按结算资产或 USD 总权益；区分 counted 与 reconciliation 角色 |
| positions / 一次观察中的合约仓位 | run_id, symbol, position_side, quantity, entry_price, mark_price, unrealized, notional, margin_asset | U(run_id,symbol,position_side)；同一合约的多空双持分行，名义仓位不进入环图 |
| quotes / 一笔选用的报价 | base, quote, price, priced_at, received_at, source, path, leg_ids | 可由多个持仓引用，保存换算腿及版本；同来源同一观测标识唯一，修正另留版本，不覆盖已用报价 |
| ledger_events / 一个来源事件的一条腿 | account_id, source, source_key, leg, wallet, asset, signed_qty, fee_qty, fee_asset, event_at, settled_at, state, price_id, usd_principal, kind, match_id, match_state, updated_at | U(account_id,source,source_key,leg)；冲正、奖励、费用和本金可分别表达，配对后保留原记录 |
| event_revisions / 事件修订前后的业务字段 | event_id, revision, changed_at, origin, before_fields, after_fields | U(event_id,revision)；和事件更新在同一事务保存，只保留脱敏字段 |
| sync_cursors / 一个账号一个拉取维度的进度 | account_id, source, dimension, committed_until, last_id, last_checked_at, coverage_gaps | U(account_id,source,dimension)，无维度时用固定非空值；只记录已读进度，不派发任务 |
| daily_marks / 单账号一个边界的权益引用 | account_id, boundary_at, batch_id, usd_equity, quality, reason, calc_version | U(account_id,boundary_at,calc_version)；只引用符合时差约束的观察，不能把混合批次当日终 |

资金美股复用同一条 holdings：asset 保存原始代码（如 EQ_MU），asset_class=us_equity，underlying_symbol=MU，钱包从所属 run 取 funding。双接口对到同一原始代码须复用 item_key。分组标签不是第二条持仓，股票成交仅进 ledger_events。bStocks 待验证，不映射为 us_equity。

components 只放适配器允许的业务字段（如 free、locked、收益明细、产品状态）；不留请求头、签名、完整链上地址等无关敏感信息。当前余额是最近成功观察的读视图；按选区计算的现金流、收益率和分布由 Go 从原始记录派生，不用数据库函数。组合日终仅聚合同批、同边界且覆盖满足要求的 daily_marks。

## 写入、查询与验收
- 归属：Go 在事务内验证账号、run、batch 归属一致，检查账号在观察时刻是否启用；只允许通过服务写业务表。停用只结束覆盖期，保留历史；不级联删除。巡检列出失联引用，修复前不计入组合。
- 持仓：一份完整钱包响应的所有页和明细一起提交。空余额只有在查询成功且该接口语义支持时才是 0。重复提交同一批 BTC 行不得翻倍；部分响应不替换上次完整明细。
- 流水：优先用稳定官方 ID。合约 income 需包含 incomeType 与 tranId；划转包含方向及 tranId；充提优先用交易所记录 ID 而非单独的链上 txId。无稳定 ID 的收益记录以官方可稳定区分的维度构造业务键；无法区分的碰撞标待核对，不静默合并。PENDING → SUCCESS 更新同一事件；来源字段变化和人工配对保留变更依据与时间（追加修订版本）。
- 索引按实际读法建：wallet_runs(account_id,wallet,observed_to DESC)、ledger_events(account_id,event_at DESC,id)、daily_marks(account_id,boundary_at)、holdings(run_id)。查询历史范围时包含当时已启用、现在已停用的账号。
- 验收：A/B 账号同号流水各保留一笔；同账号重试十次只一笔；密钥轮换历史不断；回放同批次与同价源得到相同 USD；一个父引用不匹配的持仓事务整批拒绝。
