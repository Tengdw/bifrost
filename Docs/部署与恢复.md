# 部署与恢复

运行配置和恢复命令见[部署指南](./部署指南.md)。每个只读工作区使用独立数据库和加密主密钥。

## 备份与恢复目标

生产环境尚无已验证的备份频率、保留策略、RPO/RTO 或恢复演练。部署方若为测试数据库制作备份，应明确数据敏感级别并在传输到独立设备前加密；主密钥必须单独加密备份。数据库备份与主密钥分开管理，缺少对应主密钥时，账号凭据无法解密。不要把数据库 DSN、API Secret、会话密钥或主密钥放入仓库和普通备份包。

以下命令只演示 PostgreSQL 自定义格式导出和向**新建的空隔离库**恢复。`pg_dump` 生成的文件本身未加密，必须由部署方在离开受限主机前使用其批准的加密方案保护；不要直接将明文 dump 复制到共享或异地存储。PostgreSQL 备份选项见[官方备份文档](https://www.postgresql.org/docs/current/backup-dump.html)。

~~~sh
# 使用受限 PostgreSQL service 配置，并在有访问控制的目录中操作
umask 077
pg_dump --dbname='service=bifrost_test' --format=custom --file=bifrost.dump
pg_restore --list bifrost.dump > bifrost.contents

# 仅向新建的空隔离库恢复；service 配置须指向该库
pg_restore --dbname='service=bifrost_restore' --no-owner --no-privileges --exit-on-error --single-transaction bifrost.dump
~~~

隔离恢复目标应阻断外部账号同步，使用与备份兼容的应用版本及主密钥验证数据可读。记录备份时间、代码和 schema 版本、主密钥版本、校验结果及恢复耗时。不要在生产库上试验恢复命令。

## 重启和升级回滚

当前测试 Compose 环境以单实例运行。日常重启命令及验收步骤见[部署指南](./部署指南.md)。升级前记录代码提交、镜像 ID、schema 版本并备份测试数据库；显式运行目标模式对应的迁移，随后启动并复查登录、账号、最近批次和手动刷新。

异常时先停止新实例。只有确认旧应用兼容当前 schema 后才可使用旧镜像；否则先在隔离空库验证恢复，不要对原库直接反向迁移。生产切换、故障转移和恢复时间目标尚未定义，不能据此宣称具备生产恢复能力。

## 本机演示入口

在仓库根目录运行 `./scripts/snapshot-demo.sh complete` 可启动使用临时数据库的最新持仓演示；`unpriced` 可演示缺价状态。多账号合成工作区见仓库 [README](../README.md#运行多账号工作区)。两种演示使用临时数据库，与测试部署库、只读联调库和生产库相互独立。
