# 首版部署与恢复手册
状态：实施目标，第 01 票已有本机合成持仓服务及演示库迁移；尚无生产 Compose、生产部署或生产备份。本手册中的服务名、路径、配置名和验收命令是供后续实现的约定，不表示已部署。不要把原型预览服务用于真实账号。

## 拓扑和配置
- 一个 Go 进程同时提供 Vite 静态文件、同源 /api/v1 和内存调度器。Compose 服务名 app，固定单副本；数据库 db 可改为已有 PostgreSQL。切换版本先停止旧调度实例再启动新实例，不做新旧实例并行滚动更新。Go 内无权限时不得回退为公开访问。
- 入口要求已认证的个人会话：同源 HTTPS，由受信任入口或应用校验 bifrost_session；变更请求验证 Origin、防 CSRF。若使用反向代理鉴权，app 仅允许该代理访问且不得信任客户端自填的身份头。数据库端口不暴露公网。
- 建议配置：DATABASE_URL_FILE 指向受限连接串文件，MASTER_KEY_FILE 指向挂载的解密主密钥，MASTER_KEY_VERSION 标明版本；APP_TZ=Asia/Shanghai；SYNC_ENABLED=false 用于恢复演练。生产开启同步；同一数据库只服务一个活跃调度器。不把真实连接串、API Secret 或主密钥放入仓库、日志、构建产物或普通备份包。
- 主密钥由操作方安全随机生成并独立加密备份。账号凭据在 Go 中用认证加密（如 AES-GCM，独立随机 nonce），密文与版本才入库；队列和数据库都无需获知明文。轮换时先验证新 key 可解密写入，分批重加密并核查后再停用旧版；旧备份仍需相应旧密钥。
- USD 行情源和权限必须先核验；不能连通则显示未估值，不能切成固定 1:1。开始同步前核实币安只读权限、服务器时钟与网络。接入账号时不要在命令行参数或聊天中提交密钥。

## 上线顺序与验收
1. 备份既有数据，固定镜像版本，检查配置文件权限和主密钥版本，验证生产数据库名称及迁移目标。
2. 先以关闭调度的模式执行版本化迁移（迁移工具随实现选定）；业务账号只保留必要读写权，迁移凭据分开。验证无物理外键、业务触发器或数据库调度器。
3. 建立受保护入口，登录后打开页面；未登录访问账号与资金接口应为 401/403，日志中没有敏感配置。确认无旧实例，再启动一个启用调度的 app。
4. 用一个只读账号核对四钱包原币和 USD，再接第二个。观察首次及下一次 15 分钟批次；模拟权限不足，另一账号仍更新。日终边界尚未采到前，日历缺值是预期行为。
5. 记录服务版本、schema 版本、最近完整快照时间、各来源水位。监控连续失败、超过两个周期无完整快照、价格源过期和磁盘空间；数据库可读不等于币安同步成功。

## 备份和隔离恢复
建议每日逻辑备份，变更 schema 或密钥前额外备份；示例保留 7 份每日与 4 份每周备份。操作方按能接受的数据损失调整频率。备份加密后存到与数据库不同的设备，记录校验和、镜像/schema 版本和所需主密钥版本。逻辑库备份不含集群角色，另存角色/权限配置和不含密钥的部署清单。[PostgreSQL 官方备份说明](https://www.postgresql.org/docs/current/backup-dump.html)

以下为运维示例，使用 PostgreSQL 客户端 service 定义和受限的密码文件提供连接信息。生产和演练使用不同 service；恢复目标须是**新建的空演练库**。服务名需由操作者配置，不要把示例直接指向生产恢复。

~~~sh
# 备份到当前受限目录；先确认目录有足够空间
umask 077
pg_dump --dbname='service=bifrost_prod' --format=custom --file=bifrost.dump
pg_restore --list bifrost.dump > bifrost.contents
# 只恢复到空的隔离演练库，任何错误立即中止
pg_restore --dbname='service=bifrost_restore' --no-owner --no-privileges --exit-on-error --single-transaction bifrost.dump
~~~

校验目录可读并不代表备份可用。演练库禁用同步、阻断交易所访问，用匹配版本的 app 和主密钥只读验证：账号身份数、最近完整批次、各钱包持仓行数、某个历史日的权益/流水与备份基线一致；确认可解密一条凭据但不打印明文；主密钥缺失时拒绝真实同步。恢复后单独配置最小权限并记录恢复耗时、最后可恢复时点。

## 故障切换
先隔离旧实例并保留故障库，完成隔离恢复和核对后才把服务指向恢复库；开启唯一调度器，从已提交游标续拉流水。停机期间可恢复的流水和不可重建的余额快照分别标注。若回滚应用，确认旧版本可读当前 schema；不兼容则使用匹配版本和隔离副本，不在故障库直接反向迁移。
