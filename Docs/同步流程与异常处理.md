# 同步流程与异常处理
Go 单实例负责调度。只读工作区启动时检查当前 15 分钟时段，之后在北京时间每刻钟（:00、:15、:30、:45）触发。该时段已在同一批次完整观测四个钱包数量的账号跳过自动重采，估值缺价则保留缺口。成功绑定账号后立即安排采集；用户手动刷新走同一采集器。应用持有 PostgreSQL 会话锁，防止同一工作区运行多个采集进程；数据库只记录结果、覆盖和游标。恢复演练可设 `BIFROST_DISABLE_AUTO_SYNC=1`，关闭启动、定时及绑定自动采集。

## 从触发到可展示快照
1. 冻结请求范围与触发时间，分配 batch_id；进程内按 (account_id,wallet) 排他，整组批次可有界并行，按 IP/UID 和接口权重共享限额。在途任务返回已有 batch_id，不重复调用。手动刷新单钱包不等于全账号快照。
2. Go 校正签名使用的服务器时间。获取钱包模式、所有分页、原币数量及对应报价，记录各自的观察起止时间。首版允许同批观察离预定时刻最多 **2 分钟**；批内最大观察跨度也为 2 分钟。记录真实时间，不假装交易所支持跨接口原子快照。
3. 原子提交单钱包成功数据。资产总值为完整值须满足：同批全部应跟踪钱包均有有效观察和价格，时差未超限，无归属争议。只有证实未开通的钱包才可排除；权限不足不能排除。流水覆盖另行判断：余额齐全不等于盈亏可靠。
4. 当前查询可显示带时间的上次成功金额；已估值小计另列。只有完整组合返回完整 totalUsd；含旧值或缺价时 totalUsd 为 null，给出状态与原因。持仓、当前新鲜度和日历历史用不同时间字段。
5. 来源独立拉取流水，以事件发生时间记账，不按抓取时间。首次按接口允许范围分窗、分页；后续从已提交水位前重叠拉取，建议至少回扫近 24 小时；未终结记录单独追查直至终态。分页全部提交后推进游标，失败不跳页。记录起止覆盖、接口历史上限、未知渠道及断档，不承诺全量补史。迟到或状态修正时重算受影响日期和区间，记录版本。

## 日终、走势与日历
- D 日收盘使用 D+1 日 00:00 的自动边界批次，同一边界同时作为次日期初。接受北京时间 00:00 起不足 2 分钟内完成的观测，返回实际观察时刻。已提交的边界批次固定，重启或手动刷新只能新增普通观测。在边界开始前后与在途钱包请求相遇时复用原请求，该钱包因此缺少边界观测，组合保留缺口。
- 历史从首次真实采集起积累。首次采集前、错过边界、数量观测不完整或价格缺失时保留对应日终缺口；普通余额和历史 K 线都不用于回填上线前的持仓。过去一天没有完整日终权益，曲线断开，日历显示空值。
- 首页主卡和环图共用最近已结束日的边界值，最新观察通过单独入口查询。7/30/90 天走势和月历共用同一日指标。选中同一组账号，只有两个相邻边界都完整时才计算资产变化。现金流覆盖尚未实现，净流入、盈亏和收益率留空。

## 错误与动作
| 观察结果 | 服务动作 | 对页面的影响 |
|---|---|---|
| 成功且确定无余额 / 已证实未开通 | 保存有效零值 / 保存未开通依据 | 0 / 未开通，分开显示 |
| 超时、5xx、限频 | 有限次数指数退避加抖动；429 遵守 Retry-After，受限 IP 或账号统一降速，封禁期间不发请求 | 标同步失败或限频，上次成功值带时间 |
| 权限不足、密钥失效、账号模式不支持 | 不反复重试；要求检查只读凭据或配置；未经验证不降级成未开通 | 无权限或范围外 |
| 钱包有效但价格缺失、归属不明或分页不全 | 正确区分原始持仓和可用估值；分页不全不发布完整钱包 | 保留可信数量或旧明细，标未估值/不完整 |
| 崩溃或停机 | 启动后标记中断的运行记录，释放内存锁；从最新时刻采余额、从已提交游标续拉流水 | 有覆盖的流水可恢复；缺失历史快照保持空缺 |

## 联调场景
- 12:00 三个钱包成功，第四个在 12:08 成功：12:00 组合点仍为空，12:08 的钱包仅更新当前观察；下一个满足条件的整批才形成新组合点。
- 余额同步时点击同一钱包刷新：接口返回 already_running 和原批次 ID；第二账号仍能执行。点多次不会增加流水或重复计入权益。
- 昨天日终有效、今天权限被撤销：今日快照不能覆盖昨日历史；未知日盈亏不显示为亏光。中途补齐昨天的一笔充值后，余额快照不改，只更新流量与收益。

## 订单、成交与数量核对

接入交易采集后的首个有效钱包数量观察是该账号、该钱包的起点。每次持仓成功观察触发现货和 U 本位订单采集，同一账号钱包的在途任务合并。订单采集独立于余额采集，失败会提示交易覆盖不足，余额和仓位仍可独立显示。首次发现的已有挂单注明早于起点；游标向后滚动，并重叠查询最近 10 分钟应对延迟，持久化按交易所标识去重。超过接口页大小的查询按时间拆窗。

- 现货按交易所的完整可见现货交易对目录扫描订单，补查最近执行订单的逐笔成交和 SOR 分配。发现范围不依赖当前持仓，避免遗漏两次观察之间买入后又全部卖出的交易对。目录之外的已下架交易对仍受接口覆盖限制。扫描受全局限速约束，多个账号并发时可能有延迟。见[现货 REST 接口](https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md#account-endpoints)。
- U 本位用不指定交易对的订单历史、在途订单和收入记录发现合约，再按合约获取逐笔成交。条件单独立的委托历史受专用接口约束，普通订单接口可见的订单及成交已纳入。见[U 本位订单和成交](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)。
- 重放以选定时间段内第一笔实际观察为期初，若有后续观察，使用区间内最后一笔作期末核对。现货以成交数量和报价币种金额分别加减，并从实际扣费币种减去手续费。合约按方向增加或减少带符号的仓位数量，按单向及分开的多空方向核对；费用单独显示。下单与撤单不改变总持仓或仓位。
- 差额 = 实际期末数量 − 实际期初数量 − 已记录成交解释的变化。充提、划转、申赎、资金费等可能影响钱包余额。差额代表待核对部分，即使差额为零，也不证明其他资金事件都已覆盖。
