# Bifrost 开发与代码规范

以下约定从第 01 张实施票开始执行。技术选型见[首版技术栈](./首版技术栈.md)，业务行为以[系统规格](../spec/SPEC.md)为准。

## 开发与验收

1. **完成的标准是别人能复现。** 将实施票标为 `done` 前，在票中给出可执行的命令、需要的合成输入和预期结果。涉及存储的用例写明隔离测试库的准备方式，不需要个人账号或密钥。纯文档修改只验证受影响的内容和链接。
2. **按风险选测试。** 用 Go 测试覆盖账务规则及边界值；涉及持久化和接口时，用隔离的 PostgreSQL 验证写入、读回和 API 表达。前端验证用户看见的结果和受影响的交互。不设统一覆盖率门槛。
3. **由工具处理格式。** Go 源码用 `gofmt`。评审关注命名、职责、错误处理以及是否符合验收条件。前端构建和交互检查沿用[项目验证约定](../AGENTS.md#修改与验证)。

## 后端与前端的职责

4. **按职责拆分。** Go 判断哪些持仓可估值，计算金额并给出缺失原因；存储代码负责读写并保留精度与空值。React 使用 API 给出的金额、占比和原因做展示，不根据持仓自行重算总额。是否拆包、拆文件、引入接口，取决于实际职责，不要求每个功能凑齐相同层数。
5. **业务未知与执行失败分别处理。** 缺价是有效的业务结果，仍返回股数、小计和缺价原因；查询数据库失败则返回错误，前端显示读取失败，不能显示成空钱包。Go 不静默忽略影响结果的错误，同一次失败由处理它的边界记录一次。
6. **名称表达业务含义。** 自有代码标识符用英文，区分股数、单价、美元估值与已估值小计，例如 `quantity` 与 `pricedSubtotalUSD`。交易所和已有 API 字段保持原拼写。用中文注释解释不直观的业务原因，而非逐行翻译代码。

## 项目结构

单仓库，根目录一个 Go 模块（`go.mod`），一个正式前端。下表是目标布局，随功能实施创建目录。

| 位置 | 内容 |
|---|---|
| `cmd/bifrost/` | 单一服务入口：读配置、连接数据库、组装并启动 HTTP 服务与调度器。 |
| `internal/` | 按业务功能组织 Go 包，如 `holdings`、`accounts`。HTTP、PostgreSQL 和币安适配代码与业务计算分开。 |
| `db/migrations/`、`db/queries/` | 前者存版本化迁移，后者存供 sqlc 使用的查询。 |
| `web/` | 正式 React 前端。页面按 `src/features/<功能>/` 组织，跨页面确实复用的组件放入 `src/shared/`。 |
| `ui-preview/` | 保留已确认的示例 UI，供设计对照。可复用组件和样式；正式页面通过 API 取数，失败时不回退到示例余额。 |
| `spec/`、`Docs/` | 分别维护系统行为与验收、接口契约与专项约定。 |

## Go 后端

语言风格以 [Google Go Style Guide](https://google.github.io/styleguide/go/guide.html) 和 [Style Decisions](https://google.github.io/styleguide/go/decisions.html) 为基线。包名简短、小写、表达职责；使用 `holdings` 而不是把不相关的代码收进 `common`。标识符用 Go 的大小写惯例，API 字段继续使用契约中的拼写。

- **业务与 I/O：** 持仓数量、缺价和小计的计算放在 `internal/holdings/`，其测试紧挨业务代码；调用这些函数不需要启动 HTTP、连接数据库或访问币安。HTTP 适配代码解析参数和映射响应，存储适配代码用 pgx/sqlc 读写数据。一个功能无需预建整套分层目录。
- **取消与超时：** 需要访问数据库或外部服务的操作，把调用方的 `context.Context` 作为首个参数向下传递；纯计算不额外接收上下文。独立后台同步由服务管理生命周期，勿将复用中的同步任务绑在某位用户的 HTTP 连接上。
- **错误：** 调用失败时检查并返回错误，附上能识别失败操作的上下文。领域上的“缺价”走正常结果和缺失原因；数据库或网络失败不得伪装成空持仓。

## TypeScript 与 React 前端

以[阿里巴巴前端规约](https://github.com/alibaba/f2e-spec)为主，TypeScript 以其[中文编码规约](https://github.com/alibaba/f2e-spec/blob/main/docs/coding/typescript.zh.md)为准；其中未覆盖的 TS 专题可参考 [Google TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html)。项目规格和 API 契约优先，外部指南不改变金额精度、空值或外部字段名。来源与适用范围见[代码规范来源](./代码规范来源.md)。

- **类型与模块：** 开启 TypeScript `strict`。沿用阿里规约：对象形状优先用 `interface`，联合类型用 `type`；使用 ES 模块，重载签名放在一起。确需类型断言时使用 `as`；断言不能代替对外部数据的检查。抑制编译检查的注释须说明具体原因。
- **功能与数据边界：** 持仓页面、专用组件和测试放在 `web/src/features/holdings/`。集中管理请求和契约类型；组件拿到的金额仍是十进制字符串或 `null`。只在图表需要数值时转换，保留空点；不使用 `Number(null)` 或默认零填补缺价。
- **交互：** 明确区分加载中、请求失败、已确认空仓、有持仓但缺价。失败时给出错误状态；成功返回空仓或部分持仓时，用对应的业务文案。
- **React 组件：** 遵循[阿里 React 规约](https://github.com/alibaba/f2e-spec/blob/main/docs/coding/react.md)，组件用大驼峰命名。可排序、可筛选的持仓列表用稳定的行标识作 key，不用数组下标；否则切换账号或排序后，展开状态可能落到另一笔持仓上。
- **检查：** 正式前端接入时配置 ESLint 检查代码、Prettier 统一格式，另跑类型检查和生产构建；同一种排版问题只由一个工具负责。按修改范围检查受影响的交互。

## 第 01 票的评审示例

使用[第 01 票](../.scratch/current-holdings/issues/01-funding-snapshot.md)的合成数据。现金价值 800 USD、2 股股票每股 100 USD 时，完整总额应为 1,000 USD。移除报价后，Go 仍保留 2 股和 800 USD 小计；保存并重新查询后，API 的完整总额仍为 `null`。前端应把未知总额显示为「—」，把已确认空仓的钱包显示为「0」。

如果页面通过把 `null` 转为零来画图，即使构建成功也不算验收通过。同样，如果数据库查询失败，返回空列表并提示「暂无持仓」也是错误行为。
