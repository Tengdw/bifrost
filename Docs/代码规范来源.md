# 代码规范来源

核验日期：2026-11-17。项目采用哪些规则，以[开发与代码规范](./开发与代码规范.md)为准。下面记录原始出处及其适用范围，便于评审时追溯。

| 出处 | 原文覆盖什么 | 在 Bifrost 中怎么用 |
|---|---|---|
| 阿里巴巴前端规约：[项目说明](https://github.com/alibaba/f2e-spec)、[TypeScript 规约](https://github.com/alibaba/f2e-spec/blob/main/docs/coding/typescript.md)、[React 规约](https://github.com/alibaba/f2e-spec/blob/main/docs/coding/react.md) | 阿里巴巴组织发布的前端团队规约。TS 禁止在可选链后加非空断言；React §2.3.9 建议列表避免用下标作键，§3.2 要求组件引用用大驼峰命名。 | 评审持仓列表时，检查排序、筛选后行的身份是否稳定；不要用非空断言掩盖缺价。 |
| Google：[Go Style 总览](https://google.github.io/styleguide/go/)、[Style Guide](https://google.github.io/styleguide/go/guide)、[Style Decisions](https://google.github.io/styleguide/go/decisions) | 面向 Google 的 Go 代码。Guide 给出可读性原则；Decisions 细化了错误返回、处理和小接口等规则；Best Practices 属于建议。 | 数据库出错时显式处理或返回错误，不能默认为查询成功。只有调用方确实需要抽象时才引入接口。 |
| Google：[TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html) | 建议用具体类型，未知输入可用 `unknown` 再收窄；`null` 和 `undefined` 的选择取决于接口语义。 | 金额是否可空取决于[本项目 API 契约](./API契约.yaml)。前端保留十进制字符串和显式的 `null`，不得用零替换未知金额。 |

**阿里是否有可直接引用的 Go 集团规约？** 本次未核实到与前端规约同等归属的公开 Go 手册。[阿里巴巴 P3C](https://github.com/alibaba/p3c) 明确面向 Java；阿里云开发者社区的[《Go 开发关键技术指南》](https://developer.aliyun.com/article/742169)虽介绍了 `gofmt`，但原文署名为阿里巴巴技术专家杨成立，并注明用户投稿。可以引用作者的工程经验，不足以据此认定集团统一要求。Go 格式化另有 [Go 项目自己的说明](https://go.dev/doc/faq)。
