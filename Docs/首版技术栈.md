# Bifrost 首版技术栈

定稿日期：2026-11-16。适用范围见[资产记录系统首版蓝图](./资产记录系统首版蓝图.md)。

**Go 负责定时同步和业务逻辑；PostgreSQL 只存数据，不建外键。** 首版部署一个 Go 服务，同时提供页面、REST API 和后台同步。多个币安账号共用这一个服务，分别记录各自的同步结果。

## 技术选型

| 模块 | 选型 | 职责 |
| --- | --- | --- |
| 前端 | React、TypeScript、Vite | 构建资产看板；静态文件随 Go 服务发布。 |
| 表格与图表 | Ant Design、Apache ECharts | Ant Design Table 展示账号与钱包汇总、持仓明细和资金流水；ECharts 展示估值和持币数量的历史曲线。 |
| 后端 | Go 标准库 `net/http`、REST API | 处理查询和刷新请求；在 Go 中计算资产估值、盈亏，识别内部划转。 |
| 币安接入 | 币安官方 Go SDK、自有适配层 | 使用只读密钥采集现货、资金、Simple Earn 和 U 本位合约数据，转换为统一的余额、仓位和流水记录。 |
| 数据访问 | PostgreSQL、pgx、sqlc | pgx 连接数据库，sqlc 根据读写 SQL 生成 Go 方法。 |
| 部署 | Docker Compose | 运行一个 Go 应用实例和 PostgreSQL；已有数据库可直接连接。首版不引入 River、Redis 或独立任务队列。 |

## Go 如何同步

1. 服务启动后同步一次，此后由 Go 定时器每 15 分钟触发。手动刷新和定时同步使用同一套采集逻辑。
2. Go 按“账号 + 钱包”限制并发。相同账号的同一钱包正在同步时，重复请求返回“同步中”；某一钱包失败不阻断其他钱包。
3. 网络超时由 Go 有限重试；密钥失效则记录失败原因，提示检查密钥。同步结果写入 PostgreSQL，供页面查询最近成功时间和错误原因。
4. 运行中的任务仅保存在进程内，重启后重新采集当前余额。停机期间缺失的快照保留缺口，不用重启后的余额回填。此设计以单实例调度为前提。

## PostgreSQL 的存储边界

- 保存账号、余额、仓位、资产快照、估值价格、资金流水和同步结果。数据库不调度任务，不作为队列，不用触发器或存储过程执行业务规则。
- **所有表均不声明物理外键（`FOREIGN KEY` 或 `REFERENCES`）。** 快照、流水等记录保留 `account_id` 表示归属，由 Go 在写入时校验。停用账号后保留历史记录。
- 保留主键、必要的查询索引和防重唯一索引，避免重试导致同一笔流水重复入库。
- 数量、价格和估值使用 PostgreSQL `NUMERIC` 保存，Go 使用十进制类型计算，API 用字符串传输金额。表格展示后端计算结果，仅在 ECharts 绘图时转换为数值。
