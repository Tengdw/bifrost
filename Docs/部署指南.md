# 部署指南

本指南用于先在测试环境运行当前版本：Compose 仅启动 Bifrost 应用，连接已经存在的测试 PostgreSQL。合成验收通过后，如需验证币安只读账号，再使用一个**独立的只读联调数据库**。合成环境和只读联调环境不能共用数据库；首次部署、迁移和验收都不连接生产库。

## 当前能力和后续目标

当前可部署版本支持登录、绑定只读账号、手动刷新四类钱包并查看当前持仓。合成模式只接受文档中的固定演示凭据，不请求币安。只读模式可用于人工联调，但外部行情、币安账户模式和权限仍须逐项核实。当前没有定时采集、日终历史、每日盈亏或生产部署与恢复保障；估值缺少可靠报价时应显示未知。后续能力以[系统规格](../spec/SPEC.md)和对应实现为准。

## 组成与配置

Compose 文件在仓库根目录。它只运行一个 UID `10001:10001` 的应用容器；PostgreSQL 是部署方已有的服务，不在 Compose 中创建。应用直接在容器内使用 TLS，映射到部署主机内网地址的 HTTPS 端口。仅允许获准的内网客户端访问。

在测试部署主机准备配置目录（默认示例为 `/srv/bifrost-test/secrets`），放入以下文件。文件名必须与 Compose 挂载配置一致：

| 文件 | 内容 |
|---|---|
| `database-url` | 专用测试 PostgreSQL DSN。容器内不可用 `localhost` 指代宿主机或其他数据库主机。 |
| `master-key` | 32 个随机字节的标准 Base64 文本，用于账号凭据加密。 |
| `session-token` | 至少 32 个字符的随机会话密钥。 |
| `tls.crt`、`tls.key` | 浏览器访问地址对应的证书链和私钥；证书名称须匹配 HTTPS origin，浏览器须信任其签发方。 |

确保目录和文件可由容器 UID 10001 读取。Linux 示例：目录归属 `10001:10001`、权限 `0500`；文件同归属、权限 `0400`。主密钥另行加密备份，并与数据库备份分开保管。不要把这些文件放入仓库、镜像或普通备份包。证书私钥按同等敏感配置保护。

将 `deploy/.env.example` 复制为部署主机上的 `deploy/.env`，填写非秘密配置：

```dotenv
BIFROST_IMAGE=bifrost:local
BIFROST_MODE=synthetic
BIFROST_PUBLIC_ORIGIN=https://bifrost.test.lan:8443
BIFROST_BIND_IP=部署主机内网IP
BIFROST_HTTPS_PORT=8443
BIFROST_CONFIG_DIR=/srv/bifrost-test/secrets
```

`BIFROST_PUBLIC_ORIGIN` 的主机名、证书名称和端口必须一致；`BIFROST_BIND_IP` 是部署主机实际内网地址。`.env` 仅保存路径和运行选项，不保存数据库 DSN、密钥或证书内容。不要提交 `.env`。

## 安装、迁移和启动

在部署主机检出已审阅的代码版本，并准备 Docker Engine 与 Compose 插件。确认测试 PostgreSQL 已创建，DSN 指向该测试库；数据库网络策略仅允许所需主机访问。迁移和运行使用同一测试库，迁移前确认备份与目标库身份。

从仓库根目录检查配置并构建镜像：

```sh
docker compose --env-file deploy/.env config --quiet
docker compose --env-file deploy/.env build app
```

`config --quiet` 只能检查 Compose 配置，不能证明 DSN 指向了正确数据库。人工再次核对目标环境后，显式执行与 `.env` 模式一致的迁移：

```sh
docker compose --env-file deploy/.env run --rm app -mode synthetic -migrate
```

迁移成功并核对目标 schema 后启动单实例：

```sh
docker compose --env-file deploy/.env up -d app
docker compose --env-file deploy/.env ps
docker compose --env-file deploy/.env logs --tail=100 app
```

若配置为 `readonly`，迁移命令也必须使用 `-mode readonly -migrate`，且 DSN 必须指向单独的只读联调数据库。不要把已迁移的合成数据库切换为只读实盘账号库。

## 验收

从部署主机以及另一台获准访问内网的设备打开配置中的 HTTPS 地址，例如 `https://bifrost.test.lan:8443`。确认浏览器信任证书、未登录请求受限、登录后页面可正常访问。合成模式下绑定两个示例账号，API Key 分别使用 `demo-a`、`demo-b`，示例 Secret 使用 `fixture-only`；这组固定值只适用于合成模式，不会访问币安。

选择 A 并刷新四个钱包，应显示 `8,794.40 USD`；选择 A+B 并刷新，应显示 `9,044.40 USD`。确认账号、最近批次和持仓明细可见，日志没有密钥、Secret、签名 URL 或数据库密码。重启后再次确认登录、账号及最近批次仍可读取：

```sh
docker compose --env-file deploy/.env restart app
docker compose --env-file deploy/.env ps
docker compose --env-file deploy/.env logs --tail=100 app
```

合成模式仅接受这些固定示例身份；A 的换钥演示值为 `demo-a-rotated`。`./scripts/workspace-demo.sh verify-browser` 使用自己的临时 PostgreSQL，不连接 Compose 测试库，可作为额外的本机浏览器验收。

## 只读联调

只有合成验收通过后才进行只读联调。先创建另一个空的专用测试数据库和对应 DSN，使用独立配置目录中的主密钥、会话密钥和 TLS 文件。把 `BIFROST_MODE` 改为 `readonly`，确认 Compose 仍只运行一个实例、绑定内网地址，并重复检查证书和 origin。核实 DSN 指向独立数据库后执行：

```sh
docker compose --env-file deploy/.env config --quiet
docker compose --env-file deploy/.env run --rm app -mode readonly -migrate
docker compose --env-file deploy/.env up -d app
```

联调先核对账户模式、权限、四钱包原币数量、钱包归属和报价证据。确认 USDT/USD 来源及时间、资金冻结或在途余额口径、美股交易日历与收盘价前，不输出缺乏依据的完整估值。不要在命令行、代码、日志或聊天中记录真实凭据。

## 重启、升级和回滚

日常重启使用 `docker compose --env-file deploy/.env restart app`。当前版本要求每个数据库只有一个应用实例；升级前先停止旧实例，不要新旧版本并行运行。

升级前记录当前代码提交、镜像 ID 和 schema 版本，并对当前**测试**数据库做备份。构建并固定新镜像，审阅迁移，再使用该环境对应的 `-mode synthetic -migrate` 或 `-mode readonly -migrate` 显式迁移。启动后重复验收登录、账号、最近批次、手动刷新及重启持久性。

若升级异常，先停止新版本。仅当已确认旧应用版本兼容新 schema 时才使用旧镜像回滚；否则不要直接对原库做反向迁移，应先用匹配版本在隔离的新库验证备份恢复。每次记录代码提交、镜像 ID、schema 版本、模式、数据库标识（不含 DSN）、迁移时间和验收结果。

## 本机 OrbStack 测试记录（2026-11-17）

本次只启动应用容器，迁移目标是已有的测试 PostgreSQL。Mac 能直连测试库，但容器直连超时，因此在 Mac 上使用专用 TCP 转发：容器连接 `host.docker.internal:15436`，转发进程只监听 Mac 的 `127.0.0.1:15436`。能直连测试库的部署不需要这一步。

转发由当前用户的 LaunchAgent 管理，登录时启动。若容器失去数据库连接，在 Mac 上用 `launchctl print "gui/$(id -u)/local.bifrost.test-db-relay"` 检查状态；如需重启，用 `launchctl kickstart -k "gui/$(id -u)/local.bifrost.test-db-relay"`。应用容器重启不需要重启转发。

已从 Mac 通过局域网地址验证 HTTPS 登录、四钱包刷新，以及容器重启后使用原会话读取同一批次和合成总额 8,794.40 USD。Chrome 页面验收使用本次签发证书的公钥指纹；其他设备仍需单独配置信任并验证访问。未访问生产库或币安。

## 当前限制

测试部署通过只说明当前版本在对应的合成或只读路径可运行。生产部署、生产备份与恢复演练、定时任务、历史收益能力尚未交付。本指南不授权使用生产库，也不把未来目标视为已实现功能。更完整的恢复边界见[部署与恢复](./部署与恢复.md)。
