# 部署与本地开发

## 本机开发

安装 Go 1.25.7 或更高版本、Node.js 22.13 或更高版本和 Python 3.9+，在仓库根目录运行 `make dev`。首次启动会编译后端、迁移已有的 `bifrost_test`、在终端初始化管理员并安装前端依赖。打开 http://localhost:5173 。Vite 负责前端热更新，Go 源文件或迁移变化时，启动脚本重新编译并重启后端。Ctrl+C 结束两个进程，数据库继续保留。

启动器读取根目录的 `.env`，同名进程环境变量优先。数据库凭据来自 `BIFROST_KEY_FILE`（默认根目录的 `.key`）。使用现有“数据库配置”段的两行格式：第一行是主机和端口，第二行是用户名、斜杠和密码。密码内的特殊字符会按 PostgreSQL URL 规范编码。开发和部署各自固定库名，迁移前再向数据库核对。已有合成工作区须先归档或迁出。

在浏览器用管理员账号和密码登录，进入账号管理绑定真实只读 API Key；Passkey 在登录后的安全设置中绑定。重启继续使用同一个 localhost 地址。定时同步和手动刷新共用采集服务，首页使用日终数据，「最新采集」可查看刚采到的持仓。

## 反向代理后的部署

准备已有的 PostgreSQL 数据库 `bifrost`、Docker Compose 和 Python 3。把根目录 `.env.example` 复制为 `.env`，填入用户浏览器访问的 HTTPS 地址。反代负责 TLS，保留浏览器的 Host（含非默认端口），转发到宿主机 `127.0.0.1:8080`。跨主机的代理可设置 `BIFROST_BIND_IP`，限制该端口只对代理开放。Passkey 使用固定域名，变更域名后使用密码登录并重新注册。

在交互终端运行 `make deploy`，依次构建镜像、迁移、首次创建管理员、启动一个 HTTP 应用容器。运行中升级前先停止旧实例并备份数据库。首次部署会生成随机主密钥，持久保存在私有目录 `.bifrost/bifrost`。升级旧环境或恢复备份时，在首次启动前用 `MASTER_KEY_FILE` 指向原有主密钥；开发环境对应 `BIFROST_DEV_MASTER_KEY_FILE`。数据库和匹配的主密钥需要独立备份。

部署主机可运行 `make admin-recover` 重设账号密码，同时撤销旧会话和已注册 Passkey。开发主机使用 `make dev-admin-recover`。恢复演练在独立环境中进行，用 `BIFROST_DISABLE_AUTO_SYNC=1` 禁用自动采集，并限制对交易所的网络访问。

## 验收

首次登录后注册 Passkey，退出并用 Passkey 再次登录。确认手动采集和定时采集的时间、账号与钱包范围。价格或流水缺失时，页面应显示对应原因。数据库、采集和浏览器自动化测试使用临时的合成工作区；开发库和生产库均存放真实数据。
